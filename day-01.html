01 • Observability Fundamentals
01

What is Observability?

Observability is the ability to understand what is happening inside a system by analyzing the data produced by that system.

02

Observability from an SRE Perspective

For an SRE, observability provides the evidence required to understand service health, user impact, reliability, and production behavior.

03

Observability from a DevOps Perspective

For DevOps engineers, observability provides visibility across applications, infrastructure, deployments, containers, Kubernetes, and cloud resources.

02 • Why Observability?
04

Why Do We Need Observability?

Modern distributed systems contain many interconnected components, making it difficult to identify failures without collecting and correlating system telemetry.

05

Complexity of Modern Applications

Microservices, APIs, databases, queues, containers, Kubernetes, and external services create complex request and dependency paths.

06

The Production Problem

A system can appear healthy at the infrastructure level while users experience latency, errors, failed transactions, or degraded application performance.

REAL PRODUCTION QUESTION
"CPU is normal. Memory is normal. Pods are healthy. So why is the application still slow?"
03 • Monitoring vs Observability
07

What is Monitoring?

Monitoring continuously checks predefined system conditions and alerts engineers when known thresholds or failure conditions are reached.

08

What is Observability?

Observability enables engineers to investigate system behavior and answer questions about unknown or unexpected problems.

09

Monitoring vs Observability

Monitoring focuses on detecting known problems, while observability focuses on understanding system behavior and investigating why problems occur.

Monitoring → "Something is wrong"

Observability → "What is wrong, where is it happening, and why is it happening?"
04 • Three Pillars
10

The Three Pillars of Observability

Metrics, Logs, and Traces provide complementary information that helps engineers understand different aspects of system behavior.

📊

Metrics

Numerical measurements that show system behavior and trends.

📜

Logs

Detailed records that explain events occurring inside systems.

🔍

Traces

Request journeys that show how operations move across services.

05 • Telemetry
11

What is Telemetry?

Telemetry is the collection of data generated by applications, infrastructure, and services that allows engineers to understand system behavior.

12

Telemetry Data Flow

Telemetry is generated by systems, collected by agents or collectors, stored in observability platforms, and analyzed by engineers.

Application
→
Telemetry
→
Collection
→
Storage
→
Analysis
06 • Production Observability
13

Observability in a Distributed System

Distributed-system observability connects information from multiple services and dependencies to understand the complete path of a user request.

14

Observability in Kubernetes

Kubernetes observability provides visibility into clusters, nodes, pods, containers, services, workloads, networking, and applications.

15

Observability in Cloud Environments

Cloud observability provides visibility across compute, networking, databases, containers, serverless services, and other cloud resources.

07 • SRE & Observability
16

How SREs Use Observability

SREs use observability to detect incidents, investigate failures, understand user impact, identify root causes, and verify recovery.

17

Observability & Incident Response

During incidents, observability provides the telemetry required to quickly identify symptoms, isolate affected components, and investigate the underlying cause.

18

Observability & Root Cause Analysis

Root cause analysis uses correlated telemetry and system context to determine the underlying reason behind a production failure.

08 • Observability Mindset
19

The SRE Observability Mindset

Instead of asking only whether infrastructure is healthy, SREs focus on whether users are successfully receiving the expected service.

THINK LIKE AN SRE
"Is the server healthy?" is only one question. "Is the user getting a reliable service?" is the bigger question.

20

10 • Real-World Scenario
21

Scenario: API Latency Increased

When an API becomes slow, engineers can use metrics to detect increased latency, logs to identify errors, and traces to locate the service or dependency causing the delay.

User Complaint ↓ API Latency Increased ↓ Metrics ↓ Application Logs ↓ Distributed Trace ↓ Dependency Analysis ↓ Root Cause ↓ Fix & Verify
11 • Day 1 Summary
22

Day 1 Summary

Observability combines telemetry, engineering practices, and system context to help SRE and DevOps teams understand and troubleshoot complex production environments.

DAY 1 — KEY TAKEAWAYS
Observability is not just a monitoring tool.

It is a way of understanding system behavior using Metrics, Logs, Traces, and other telemetry.
